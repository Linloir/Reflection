# 测试与验收

## 可重复的核心检查

```bash
python3 reflection test
```

这个入口运行 Python 协议测试、Android 纯 Java 核心与传输检查，以及当前
平台可运行的原生核心检查。macOS 的独立检查程序不要求 XCTest；
完整 Xcode 环境也可运行 Swift 包中的 XCTest。

单独运行真实原生宿主的协议集成检查：

```bash
python3 tools/check_host.py --server PATH_TO_NATIVE_EXECUTABLE
python3 tools/check_controls.py --server PATH_TO_NATIVE_EXECUTABLE
```

脚本创建临时配置与随机密钥，只启动 `--dry-run`，测试互认证、笔阶段、
篡改、重复序号、心跳重放、反射 pong、重复能力帧、NaN、超大帧、空闲超时
和新会话恢复。不会控制系统鼠标，也不会改写现有配置。

`check_controls.py` 另外验证整组设置失败时不改配置、profile 往返及密钥隔离、
重名/非法名称拒绝、同配置重复启动、协作停止和重启。macOS 还检查通过符号
链接修改配置后控制身份保持一致。全部使用独立临时配置及无输入模式。

Windows 上这两个脚本自动使用 Windows 配置命令，也可显式传入
`--platform windows`。

## 桌面 UI

```bash
python3 reflection build ui
python3 reflection install ui
python3 reflection ui
```

先在连接页勾选 dry-run，以免操作测试时向前台应用注入输入。检查：

1. 压感预设、拖动点与数字编辑反映到同一曲线；加载后曲线不变形。
2. 保存两套 profile，切换映射、倾斜和坐标级数；连接密钥与端口不变。
3. 启动、停止、应用后重启；重复点击不产生多个宿主。
4. UI 打开时从 CLI 修改同一配置，旧 UI 内容不能静默覆盖外部更改。
5. 退出 UI 时释放自己启动的宿主；从 CLI 独立启动的宿主继续运行。
6. macOS 26+ / 旧版、Win11 / Win10 的导航、主题、高对比度、多屏缩放和可访问性。

macOS 27.0.1 已实际验证窗口、曲线拖点、profile 保存、dry-run 启停重启、
外部配置冲突提示以及关闭窗口后的自有宿主退出。旧版 macOS 目前仅检查
API availability 分支，不能代替实际机器验收。Windows 的 C# 类型检查和
C++ 交叉编译不包含 XAML 编译与窗口运行，需在 Windows 构建并完成上述项目。

## Android 实机诊断

```bash
python3 reflection android devices
python3 reflection android status
python3 reflection android selftest
```

`selftest` 在 Android 进程内构造 MotionEvent，经过采集适配器和正常传输，
不是让硬件产生真实压力。返回值明确包含 `synthetic: true`、
`hardwareVerified: false`。

### 系统输入调度与 ANR

`selftest` 和纯 Java 测试不经过 Android 的窗口输入队列，不能验证输入调度
是否卡住。需要在真实系统上覆盖悬停、落笔、连续移动、抬笔、取消、重新进入，
并分别测试普通笔、橡皮擦和手指触摸。自动注入必须经过系统输入分发；
测试时先断开宿主连接，避免合成笔事件操作电脑上的前台应用。

Android 10 及更早版本应保持系统批处理；Android 11+ 才对笔和橡皮擦落笔
请求立即交付。验收时先关闭本地预览，连续书写后停顿，再快速重新落笔，
观察样本计数是否持续增长。然后打开预览重复检查，区分输入采集与渲染问题。
同时核对每批历史点的顺序，以及落笔、抬笔和取消是否完整。

遇到“没有响应”时，在重启应用之前保留现场：

```sh
adb shell dumpsys activity lastanr
adb shell dumpsys activity top
adb shell dumpsys input
adb logcat -b events -d -s am_anr
```

检查 Reflection 的主线程、窗口输入队列及批处理调度状态。主线程空闲并不能
排除输入队列停滞；CLI 状态查询仍然响应也不能单独判为通过。旧系统还应确认
Reflection 窗口没有遗留 `mConsumeBatchedInputImmediatelyScheduled=true`。
`dumpsys input` 同时可能包含当前队列和上次 ANR 的快照，不能把旧快照当成当前
积压。比较前后 ANR 记录、持续采样进度、当前队列是否排空，以及最终是否释放笔。

### 物理笔验收

物理笔验收需要人工执行：

1. 从轻到重画线，检查压力连续性、低压力起笔和抬笔。
2. 画直线、圆、屏幕边缘和角落，检查区域映射、旋转及比例。
3. 测试笔尖悬停、侧键、橡皮端、离开感应区。
4. 接触时拔线、断网、切后台、锁屏、旋转，检查宿主抬笔。
5. 重连后先移动悬停，再重新落笔，确认没有接续旧笔画。
6. 分别测试应用的压力、倾斜、橡皮擦设置，而不只看系统光标。
7. 快速连续写 W、折线和小圆，检查起笔及早期转折，不能只观察结束位置。
8. 对比防抖开关下的静止噪声、刻意慢速微动和突然转向；校准失败应保留旧结果，
   取消应退出采集，删除校准应恢复默认参数。

倾斜需要单独对照采集和输出：

1. 分别设置客户端 `auto`、`standard`、`off`，确认 UI / CLI 一致且重启应用后保留，
   切换时不会遗留接触或改变压力、坐标采集。
2. 固定笔尖位置，按屏幕方向缓慢改变笔杆姿态；同时记录原始轴、处理状态与输出倾角。
   旋转设备后重做，避免把数字化器安装方向误当作屏幕方向。
3. 在普通设备上核验 Auto 与标准路径一致；不匹配的设备不能仅因出现一个异常值
   就触发 Note2 兼容解码。已匹配设备也必须符合受支持的数据格式。
4. 用输入适配器回归用例插入短暂异常再恢复合法输入，检查有界恢复不锁死整个接近周期；
   异常持续时应保持明确的不可用状态，位置与压力继续前进。
5. 对 Note2 一维恢复检查姿态变化、符号、旋转和未知输入拒绝；没有第二个独立角度
   时不能记录为二维倾斜通过，也不能用笔迹方向或压力补造验收结果。已测竖屏方向的
   定向检查确认恢复轴对应屏幕上下方向；其他旋转仍需实机验收。
6. 在目标应用中选择实际使用倾斜的画笔，与客户端 Off 作对照。宿主最后样本和
   1 Hz 状态截图只能辅助诊断，不能替代接触过程中的连续观察。
7. 用 `python3 reflection android tilt reset` 或 Retry detection 重启识别，确认模式、
   累计计数和防抖校准不变；重新建立的识别结果应跨笔离开/重新进入保留。

Android 核心检查包含带历史样本的快速 W，确保 DOWN 和所有历史点按序输出；
另有不同采样率下的防抖和校准质量检查。Mac 核心检查覆盖首个拖动事件的
桌面移动增量、亚像素累计、负坐标及释放边界。这些检查不模拟目标应用完整的
手势识别与事件合并行为，仍需实际画布验证。

将原始捕获与截图保存在被忽略的 `captures/` 或 `.local/` 中。公开报告只保留
必要的设备型号、系统版本、能力状态和统计结果，移除密钥、地址及个人内容。

## 延迟与稳定性

需要区分至少四个指标：

| 指标 | 含义 |
| --- | --- |
| 笔事件采样率 | Android 实际交付多少笔样本 |
| 本地排队时间 | 样本从采集到发送等待多久 |
| 心跳 RTT | 同一连接上请求与响应的往返时间 |
| 笔尖到墨迹 | 包括数字化器、系统、网络、应用和显示器的完整感知延迟 |

`android status.rttMicros` 是平板连接的 RTT。`reflection probe` 是运行该工具
的机器与宿主之间的 RTT。两者均不等于单向延迟，也不应简单除以二后当作
笔尖到墨迹延迟。

分别记录 USB、Wi-Fi 和蓝牙的 p50、p95、p99，以及持续书写时的断连次数、
队列溢出和丢失笔画。跨机器单向耗时需要时钟同步或专门测量设计；不能直接
用 Android 与桌面的单调时钟相减。

端到端延迟宜通过高速摄像、接触传感或可控显示测试测量。电子纸本地预览
与电脑目标应用的刷新是两条独立路径。

## 已验证与未验证

当前代码具有跨语言协议向量、映射与异常数据检查；Android APK 在 Note2 /
Android 9 上安装运行，Mac 的真实宿主进程完成认证与解析集成检查；
Windows 原生宿主已完成交叉编译。核心检查覆盖自定义压力曲线、坐标量化时
保留相对位置累计、倾斜开关/比例及 profiles。实际 Freeform 橡皮擦兼容性结果
见 [兼容性说明](compatibility.md)。

尚不能据此宣称完成以下验收：所有 Windows 运行场景、所有应用压感、
蓝牙硬件互通、Tab10C Pro、所有最低支持 Android 版本、iPad、
BOOX 快速墨迹、长期满负载稳定性或完整笔尖到墨迹性能。
Note2 的限定一维恢复也不能作为完整二维倾斜、所有固件或所有屏幕方向均已验证的依据。
已测固件对应内核的解析错误已确认，但驱动丢弃字节的实际内容尚未直接观察；
驱动分析不等于第二轴物理采样验收。
