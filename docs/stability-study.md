# Note2 输入稳定性研究

2026-10-26，在 Windows、Inkodo、两块横向排列的 3840×2160 屏幕环境中，
通过被动读取 Note2 数字化器事件和临时本机 TCP 中继，录制用户静止、慢线和小字输入。
本次是软件链路和滤波行为研究，不是硬件精度认证。

## 测到了什么

- 收到 26,116 个原始协议笔点；其中 1,029 个相邻点间隔恰好为 1 ns（约 3.94%）。
  旧 Android 发送器为使毫秒时间严格递增，错误地加了 1 ns；现在保留非递减设备时间，
  并继续使用严格递增序号验证顺序。同时间戳的位置不会再被当成极短间隔的新运动参与滤波。
  当前速度低通的时间系数会抵消部分差分放大；实测静止段中，仅修正时间戳的 RMS 改变很小，
  因此不把这个确定的软件错误称为本次抖动的主因。
- `/dev/input/event2` 输出 23,271 个事件报告，没有 `SYN_DROPPED`。
  运动期间报告间隔中位数约 2.806 ms；系统仍可能合批、重复或插入 MotionEvent。
- 24,486 对驱动/Android 坐标能通过一个固定旋转、缩放、平移变换匹配到浮点舍入量级：
  每轴残差标准差约 `3×10^-8` 个输入区域单位。这支持“多数坐标波动在网络传输前就存在”，
  但不能区分笔尖真实移动、传感器、固件或驱动，更不能仅据此确诊电磁干扰。
  附近时间重新匹配可解释另外 940 个重复/时序差异点；仍有少量点不能精确对应，
  所以不能据此排除 Android 重采样或事件处理对个别点的影响。
- 第一段约 19.3 秒持续接触中，按 1 秒窗口去除线性趋势后，轴向 MAD 噪声估计中位数：
  X 约 `0.000138`，Y 约 `0.0000374`。X 窗口的第 10–90 百分位约为
  `0.000119–0.000154`；这次静止段没有出现数量级的噪声突增。
- 上述 X 尺度对应单屏约 0.53 像素、双屏约 1.06 像素。驱动一个 X 方向量化步长
  映射到双屏约 0.51 像素。映射放大噪声的直觉成立，屏幕布局本身无需产生新噪声。
- 四个静止窗口没有一致的 50/60 Hz 主峰；附近单一正弦分量只解释约 0.3%–1.6% 方差。
  不启用未经验证的固定频率陷波。低频偏移也可能是真实握笔运动，不能全部当作噪声。

原始数据、实测图和分析 JSON 保存在本机 `.local/stability-study/`，不进入版本库。
记录不包含配对密钥或会话认证数据。中继增加了网络跳转，因此接收时间不能用来代表
平常使用时的端到端延迟。该轮还观察到一次 Windows 注入错误 87；当前证据不足以把它
归因于传感器噪声。最后两点位置、压力、按钮、倾斜完全相同，后续版本合并短间隔内完全
重复的 UPDATE，保留静止刷新和所有状态改变，并扩大错误诊断字段。

## 可以建模的部分和边界

观测可以写成 `z(t) = p(t) + b(t) + a(t)sin(φ(t)) + ε(t) + o(t)`：
真实笔迹、缓慢漂移、周期分量、随机噪声、偶发异常。只有一条坐标流时，不能唯一分离这些项。
例如 5 Hz 的笔画与 5 Hz 的扰动可能具有相同观测。滤波必须同时检查延迟、转角、小圈和起收笔。

在线估计采用短窗口的二阶差分，去掉恒定速度分量；对近似独立白噪声，等间隔二差分的方差
是位置噪声的 6 倍。非等间隔时使用间隔比和相应的系数能量归一化，再用 MAD 抑制少量异常点。
X/Y 分别估计；不合适的时间间隔和明显一致的曲率不更新估计。校准值作为保守下限，运行中
估计只调整允许的平滑修正幅度，不修改保存的校准值，也不从测量速度中强行扣除“噪声速度”。

估计上升快于回落：短暂较强噪声可以提升平滑预算，恢复安静后缓慢降低。无足够分辨水平的
量化窗口不用于学习更大的噪声；历史高估计按恢复时间退回校准起点，长时间停笔后重置。
与所有因果估计一样，
噪声突变刚发生时存在适应时间。相关噪声和低频干扰会使白噪声估计失准；本实现不宣称消除它们。

映射的影响用 `Σ屏幕 = J Σ平板 Jᵀ` 表示。横向映射宽度加倍时，横向标准差加倍、方差变为四倍。
滤波在平板归一化空间执行，使切换屏幕不直接改变算法对同一手部动作的判断。

## 横竖笔画的额外实验模式

用户后续提供了固定粗细的横、竖线，竖线具有局部横向毛刺，排除了压感线宽变化这一解释。
进一步消融发现：原实现不但共享移动速度，还会把二维修正向量整体压缩到圆形限幅范围。
快速纵向运动的低通滞后可能占据大部分修正量，连带减小横向噪声的修正。

`stabilization.independent_axes`（Mac 为 `independentAxes`）是**默认关闭**的实验选项。
它保留共享低通截止频率，修正预算分别使用 X/Y 平滑速度，并分别限幅；不做整体圆形缩放。
它不依赖在线噪声开关，关闭在线估计时仍可使用固定校准尺度。

原始私有笔迹中，统一按 raw 低频趋势选取竖向片段后，横向高频残差 RMS 约从 0.433 降至
0.293 屏幕像素（约 32%）。这不是带真值的定位误差，也不是新的实机测量；横向片段残差
约增加 1%，整字二维高频残差约增加 3%。同一笔迹的残差下降不能单独证明更接近用户意图。

另用 0°/30°/45°/60°/90° 的直线、圆和转角，叠加六种工况、三个随机种子做方向检验。
仿真快速竖线的法向 RMSE 降低约 61%，但 45° 和 60° 快线分别可能增加约 9% 和 26%。
无噪声小圆的半径比从 0.9897 变为 0.9776，等效相位滞后从约 2.39 ms 变为 3.63 ms。
因此保留均衡模式作为默认，不宣称这个选项普遍更优，也不同时启用表现更差的按轴截止频率。

## Windows 静止状态维护

注入错误 87 既在按侧键接触时出现，也在没有侧键的悬浮移动中出现；重复坐标不是已证实原因。
保留错误即安全终止当前会话的行为，不盲重试 87，也不把失败的 MOVE 改成新的 DOWN。

增加已有指针状态的 50 ms UPDATE 保活，避免合法静止输入没有新采样时系统状态过期；
只有仍在范围内的已有指针会刷新，不能产生新的 DOWN。UP 后只能刷新无压力的悬浮状态。
校准释放、退出和断线停止刷新，屏幕布局改变时不重播旧虚拟坐标。
这是针对已知空闲风险的维护措施，尚不能断言它解释或修复了本次全部 87。
[Sunshine 的笔输入保活实现与经验记录](https://github.com/LizardByte/Sunshine/blob/v0.23.1/src/platform/windows/input.cpp)
提供了参考；这是该项目的经验，不是 Microsoft 对 PT_PEN 超时阈值的保证。

错误日志区分 source/keepalive，记录来源时间差、距前次成功 API 调用时长、压力、倾角、
掩码、指针状态，便于验证空闲和合批假设。网络接收仍保留原有超时检查；保活不延长认证期限。

## 研究依据

- [One Euro Filter 原论文](https://gery.casiez.net/publications/CHI2012-casiez.pdf)：
  速度自适应低通的延迟/抖动取舍；它本身不是在线噪声识别器。
- [NIST MAD 定义](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/mad.htm)：
  稳健尺度估计；高斯尺度换算不等于证明实际噪声为高斯。
- [AOSP getevent](https://source.android.com/docs/core/interaction/input/getevent)：
  驱动事件观察工具，不能单靠它分离硬件与驱动。
- [BOOX EMR 校准说明](https://help.boox.com/hc/en-us/articles/37475376890004-Stylus-Calibration-EMR)：
  磁性附件可能影响 EMR；这是可用 A/B 实验检验的原因之一，不是本次诊断结论。
- [NI 采样与混叠说明](https://www.ni.com/en/shop/data-acquisition/measurement-fundamentals/analog-fundamentals/acquiring-an-analog-signal--bandwidth--nyquist-sampling-theorem-.html)：
  采样后的峰值不唯一对应物理干扰频率。

若继续做物理 A/B，应每次只改一个变量、重复记录：笔尖位置/倾斜、磁性保护套或支架、附近电源。
充电与电池对比应尽量保持相同传输方式；拔 USB 同时改变供电和传输会混淆结论。
