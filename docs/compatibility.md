# 兼容性与能力边界

Reflection 的数据链路与系统后端是不同的验证层级。收到一个合法笔样本，只能
说明采集、传输、解析和映射路径正常；不能证明任意目标应用已经把它作为完整
数位板输入消费。

## Android 和设备

| 能力 | 处理方式 | 边界 |
| --- | --- | --- |
| 压感 | 按 Android MotionRange 归一化，传输 float32 | 没有压力轴的设备不能补出压感 |
| 历史样本 | 按顺序展开 MotionEvent 历史数据 | 硬件采样率由设备决定 |
| 倾斜 | 标准 Android 轴转换；限定 Note2 输入的一维兼容恢复 | 异常后有界恢复；缺少的第二轴无法补造，可靠性见平板诊断 |
| 橡皮擦 | 接收 `TOOL_TYPE_ERASER` | 需要笔、驱动和应用实际支持 |
| 侧键 | 传输两位侧键状态 | 系统后端可表达的动作可能不同 |
| 悬停 / 离开 | 独立阶段与距离值 | 部分设备不报告距离或可靠离开事件 |
| 手掌 | 笔接近或接触时抑制触摸，分离笔与手指输入 | 依赖设备正确报告工具类型和接近状态 |
| 触摸板 | 可选单指移动、点击、滚动与多指操作；按宿主能力协商原始触点 | Windows 原生后端待实机验收；macOS 当前为兼容方式，完整原生手势尚未实现 |
| 电子纸预览 | 可选 Canvas 笔迹、模块化区域刷新与末尾渐隐，默认关闭预览 | 不等同 BOOX 直接快速墨迹；刷新速度与残影需实机验收 |

最低 API 21 是构建和接口选择的下限，**不表示所有 Android 5–8 设备已经测试**。
Note2 / Android 9 已完成 APK 安装、ADB 配置和链路验证。Tab10C Pro、
其他厂商、其他系统版本还需要独立验收。

### Note2 倾斜与橡皮擦

Note2 / Android 9 的系统输入信息报告压力范围 0..4095。已观察到该设备在内核
输入层上报超出其声明范围的倾斜值，应用层也收到超过 Android `0..π/2`
约定的 tilt。对已测固件 3.5（构建 11030）的对应内核核对确认，这是设备驱动的
报告解析错误：驱动收到 17 字节笔报告，却把两个单字节值分别作为两条倾斜轴上报，
没有解析末尾四个字节。结合实机采样，这两个上报值实际组成一条角度通道；
Android 再按两个独立倾角处理时产生异常。此结论不代表所有 Note2 固件或笔都相同。

Android 默认 `auto` 模式仅在设备及输入特征匹配时使用
兼容解码，恢复这一维通道并结合系统输入方向表达，不需要用户校准。该链路没有提供
第二条独立角度，**一维恢复不等于完整二维倾斜支持**。定向实机检查已确认，在已测
竖屏方向可恢复屏幕上下方向的倾斜，屏幕左右方向仍缺失。其他旋转的坐标转换通过了
单元测试，但尚未分别完成实机验收。
当前测试固件暴露的可恢复角度以 1° 步进，这不代表笔传感器的原始分辨率；
软件无法补回输入链路未提供的角度细节。

此兼容范围不会扩大到所有 Note2、BOOX 或 Android 设备。未匹配设备继续使用标准
Android 采集，`standard` 模式可显式关闭兼容解码，`off` 则关闭倾斜输出。这些模式
由客户端 UI / CLI 持久保存，与宿主 profile 独立。标准路径在异常后采用有界恢复，
持续合法的样本可以在同一接近周期内恢复，不因一个坏样本无限期保持零。
坐标、压力、按钮和历史采样继续传输，不等待倾斜恢复。

用 Android CLI 的 `status` 比较原始值、`tiltStatus`、异常/降级计数和最终输出，
区分标准输入、一维恢复、等待恢复、不可用及关闭。`tiltReliable` 不是完整二维能力的
证明。宿主协议 v1 不传逐样本有效性，收到零值也不能直接判断没有倾斜硬件。

已检查的 Onyx Pen SDK 虽有 `tiltX/tiltY` 原始回调，读取的仍是同一组内核事件，
得不到驱动已经丢弃的报告字节；厂商笔迹渲染库也不会重新采集这些数据。
完整修复需要在设备驱动中正确解析并上报原始报告。当前尚未直接观察被丢弃字节的
实际内容，因此不能断言其中一定包含有效的第二轴，也不能断言硬件本身缺少第二轴。
增加 SDK 依赖或调整宿主参数都不能补回现有输入链路未提供的数据。

`eraserSamples` 与 `lastRawToolType` 可确认 Android 是否实际收到橡皮擦，
`barrelButtonSamples` 与 `lastRawButtons` 则单独报告侧键。标准 Android eraser
工具类型为 `4`，Reflection 传输样本的 eraser 工具编号为 `2`，两者不要混淆。
侧键不会自动转换成橡皮擦。驱动声明支持 eraser，不代表当前笔一定发出该工具；
需要比较真实操作前后的计数。详细字段见 [Android README](../client/android/README.md)。

## macOS

当前后端产生 Quartz tablet / mouse 事件，表达坐标、压力、倾斜、工具接近、
橡皮擦和侧键。它需要辅助功能权限，**不注册虚拟 HID 数位板**。

CGEvent 字段可容纳的压力精度与应用最终读取的 NSEvent 路径并不相同。
一些嵌入鼠标事件的读取路径会进一步量化压力。高精度字段自检通过，也不能
代替在实际绘画应用中检查压力曲线。具体事件模式和已知限制见
[macOS README](../server/macos/README.md)。

查询原始 HID、枚举特定厂商设备、依赖专用驱动配置的应用可能不识别该后端。
macOS 权限检查通过同样不等于所有目标应用验证通过。

### 原生界面

桌面应用采用 SwiftUI，最低部署版本为 macOS 12。macOS 26 及更新系统走
Liquid Glass API；较旧系统使用系统材质，macOS 12 的导航使用独立回退分支。
界面与 CLI 共用配置和输入核心，UI 外观不改变笔采样和注入路径。
版本分支已实现，但不能用一个系统上的运行结果代替所有旧系统的实际验收。
构建要求和操作入口见 [macOS README](../server/macos/README.md)。

### Freeform 橡皮擦

在 **macOS 27.0.1、Freeform 5.0（656.1.2）** 上，独立空白画布的测试结果如下。
这些是系统注入与应用兼容性测试，不是物理笔硬件验证。

| 接收端与事件方式 | 观察结果 |
| --- | --- |
| 独立 AppKit 接收程序，Quartz 默认事件路径 | 实际收到笔退出、eraser 进入及匹配设备 ID 的点事件；抬笔和取消均正常释放 |
| 独立 AppKit 接收程序，额外发送 tabletPoint | 同样收到正确的 eraser 接近序列与压力，结束后无残留接近状态 |
| Freeform 铅笔，Quartz 默认事件路径 | eraser 轨迹仍画出新线，没有自动擦除 |
| Freeform 铅笔，额外发送 tabletPoint | 同样没有自动擦除 |
| Freeform 铅笔，补充 SDK 定义的设备能力标志 | 同样没有自动擦除；这不是当前默认后端的修改 |

可在新建空白画布中复验：选中铅笔，先发送 pen 水平笔画，再退出 pen 接近状态，
进入 eraser 接近状态，以 eraser 笔画垂直穿过原线，最后抬笔并退出接近状态。
确认客户端或接收诊断显示的是 eraser 工具，不能只按下一个侧键就认为已经测试了
橡皮擦。上述 Freeform 测试得到两条相交笔迹，而非擦除缺口。

AppKit 的工具信息确实能到达另一个应用，不等于 Freeform 会自动切换工具。
这些结果确认了当前 **Freeform / Quartz 输入路径的兼容边界**，不能推广为
Freeform 对所有真实数位板或所有输入后端都不支持橡皮擦。需要擦除时可先在应用内
选择橡皮擦工具；Reflection 当前不注入应用快捷键来代替工具切换。

## Windows

当前后端使用系统 Synthetic Pointer 的 `PT_PEN`，面向 Windows Ink /
Pointer 输入消费者，最低 Windows 10 1809。

- 系统压力字段范围为 0..1024；传输保留的 4096 级数据到此会重新量化。
- 倾斜按系统要求转换为角度，橡皮擦与笔侧键使用系统标志。
- WinTab-only 应用不在此后端支持范围。某些应用可以切换到 Windows Ink。
- 完整性级别、受保护桌面和应用自己的输入策略会影响注入。
- 当前已通过完整 Windows 可执行文件的交叉编译；尚未在 Windows 真机运行。

原生桌面界面使用 WinUI 3，最低运行系统声明为 Windows 10 1809。
Windows 11 在系统报告支持 Mica 时使用该材质，Windows 10 及不满足材质条件
的环境保留系统主题背景与 WinUI 控件。UI 通过同一 CLI 配置和管理 C++ 宿主，
不会把笔输入放到界面线程。WinUI 的 XAML 构建和窗口运行仍需 Windows 工具链
与真机验收；源码检查不能证明 Windows 10/11 上的实际呈现已经通过。

可运行程序、源码测试和交叉编译都不能替代在 Windows 上检查驱动、蓝牙、
多显示器、缩放和目标应用。

## 连接方式验证

| 路径 | 实现状态 | 验证要求 |
| --- | --- | --- |
| USB / ADB reverse | 已实现 | 核验设备认证、收样、拔线释放和重连 |
| Wi-Fi / TCP | 已实现 | 核验真实局域网、拥塞与断网行为 |
| Bluetooth RFCOMM | 三端均有实现 | 尚需实际配对、收样、拔适配器和重连测试 |
| iPad | 尚未实现 | 原生采集及 USB / 蓝牙协议需单独开发 |

不要用鼠标移动正常代替压感通过；不要用合成测试代替物理笔通过；不要用
网络 RTT 代替端到端书写延迟。详见 [测试指南](testing.md)。
